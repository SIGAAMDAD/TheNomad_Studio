# Retirement and authority cutover seam

`legacy-retirement.v1.json` binds W01/W02/W03/W04/W05 **historical labels** to human-assigned manual specialties. W06 and other V1 manuals are migration inputs, not runnable triggers. Preserve original event IDs, labels, message content and timestamps for audit, and continue to accept historical receipts as `ARCHIVE_ONLY` through a versioned compatibility transform. Never map old W profile names to a new model execution webhook. No GitHub issue/PR event, scheduled job, Drive change or SQL queue may launch paid AI execution. GitHub Actions may still perform deterministic CI/reporting, but obsolete active routing belongs to WG-G removal and WG-B prompt migration, not this contract patch.

Cutover requires an actual owner decision recording `BASELINE_CHANGE_ID`, approved scope digest, policy revision, trusted signer, timestamp and cutover watermark after reconciling GitHub runtime, Drive queues and SQL shadow. Reconcile independently verified source SHA, document revisions, queued assignments, current epochs, active leases, deduplication cursors, and historical attempt records. After the watermark, PostgreSQL is sole live runtime state writer; historical JSON/Drive queues become read-only projections. Owner controls rollback to a single prior writer. No cutover/merge/spend/source-game permissions change through a contract commit or a successful parser test. A missing decision keeps new runtime shadow-only and privileged publication disabled.

Owners: WG-B handles worker/prompt dispatch removal, WG-C handles PG migrations, WG-D handles isolated gateway, WG-E handles separate Oversight authority, WG-F handles compatible runtime adapter, WG-G handles provider publication+legacy router removal, WG-H independent attacks, WG-I final gated integration.
