# PUBLISH-V16/1 - scoped source and document saga

`publish-intent` is an immutable gateway request, never direct permission to push. Caller is identified from independently authenticated gateway session; client-supplied `principal_id`, `grant_id`, `independent_qa` and `owner_decision_ref` are cross-checked against server-trusted owner/QA/CI ledgers, exact artifact digest, job scope, current SHA, lease and epoch. Shared owner connector is never a verified worker identity. No worker is allowed to merge a canonical branch; source `operation` is only `SOURCE_BRANCH_UPDATE` and target must be the authorized work branch. Owner/head release gates must be independently checked before any later privileged merge/deployment/canon change.

A source publication targets exactly `{repo_id,work_branch,source_base_sha,patch_sha256,proposed_tree_sha256,changed_paths}`. Gateway checks both sides of renames, Git tree path ownership, symlinks, submodules, case normalization, current branch HEAD vs `source_base_sha`, independently tested patch/QA subject, current owner decision and live lease; rejects HEAD drift as `REBASE_REQUIRED` rather than force-writing. `proposed_tree_sha256` is a SHA-256 digest of a deterministic tree manifest, **not** a Git 40-character tree OID. Use `artifact_sha256` for the submitted patch/archive itself.

A Drive publication targets `{file_id,expected_revision,exported_sha256,document_owner_ref}`. Check source document, owner approval, correct Drive scope, document writer lease and compare-and-swap revision precondition. On conflicting revision return `DOCUMENT_CONFLICT`, no silent overwrite; when promoted to canon, require separately verified owner approval and exact independently QA-accepted export hash.

`publish-readback` has `PREPARED`, `EXTERNAL_OBSERVED`, `VERIFIED`, `CONFLICT`, `BLOCKED`. `VERIFIED` requires a matching provider readback object and UTC verification time: GitHub work branch commit SHA, deterministic tree/artifact digest, or Drive file+revision+exported digest. **Only after readback matches the recorded intent** may DB record a reconciled provider effect. External timeout/unconfirmed API success remains pending; read back before retry with the same `idempotency_key`. Replaying an identical key/digest is harmless; changed payload under an existing key is `IDEMPOTENCY_CONFLICT`. Do not publish case plaintext, keys or source game content in an audit log.

Gateway, GitHub App setup, branch restrictions and actual provider write adapter belong to WG-D/G. The schema and synthetic fixture provide neither gateway credentials nor live write permission.
