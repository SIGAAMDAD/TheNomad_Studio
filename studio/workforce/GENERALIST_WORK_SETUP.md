# V1.6 — manual High engineering workforce

**Active launch method:** `USER_OPENED_MANUAL_CHAT` only. Human opens a GPT-6 High chat on an approved job. No native Work task subscriptions, GitHub PR-triggered AI, paid model automation or scheduled model workers. W01–W05 labels and Sxx slots belong solely to history; no creation, activation or label routing is permitted. This supersedes V2 event-worker setup instructions without deleting previous immutable receipts.

Use the single [`manual worker kernel`](../v16/worker/README.md), [manual launchers](../v16/worker/MANUAL_LAUNCHERS.md), and [role registry](../v16/worker/ROLE_REGISTRY.v1.json). Look up one of 174 role manuals and owner-led department mapping; never load all 174 into each worker context. Exact source selection comes from [`source_targets.v1.json`](source_targets.v1.json), never from the historical W profile. The owner must explicitly approve each job and access; a job JSON/label cannot prove approval.

First external GitHub/Drive access in every new chat: state provider, exact repository/ref/path or Drive file/folder, READ/WRITE operation, and reason; obtain the human's confirmation **before** making that connector call. Platform consent is not Studio job authority. With supplied ZIPs, work offline immediately, with empty preflight; do not request access you do not need. No independent gateway identity => no privileged remote write or merge; return local patch, hash evidence and `LEDGER_WRITE_PENDING` if no external readback.

One response = one bounded attempt/shift. Juniors: fixtures/narrow files. Mid-level: bounded feature completion. Senior debugger: difficult repairs. Senior integrator: staging-only, verified upstream. Independent QA: read-only with exact source SHA. Heads: departmental DAG and scoped handoff. No worker merges canonical branches, accepts canon, authorizes paid spending or self-reviews. Resuming requires a **new** attempted response and exact RUN-V16 capsule, with epoch/lease and source readback reverified before privilege.

The old `WORKER_PROMPTS_V2.md` and `hierarchy.v2.json` are archive/compatibility only. They must not be copied into a live Work task. WG-G owns removal of the executable runtime/CI route. WG-B does not modify scripts or GitHub Actions.
