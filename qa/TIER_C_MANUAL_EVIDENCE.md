# Tier C witnessing — actual manually initiated ChatGPT sessions

The operator/witness performs this only with an actual selected project, existing GitHub repo/ref, connected ChatGPT GitHub app, genuine trusted Studio service, and configured CI/.NET game toolchain. No automated ChatGPT spawning or model-API invocation.

1. Record actual chosen project ID, configured repo/ref, initial GitHub HEAD, Canon snapshot, source SHA and pinned skill/role digests. Keep credential contents out of logs.
2. Manually start **two independent ordinary browser conversations** and record human-observed launch timestamps and prompt hashes. A session cannot be proven a unique browser identity solely from the shared GitHub account.
3. Chat A writes actual immutable self-addressed `HELLO` and relay assignment; Chat B polls the configured inbound path and writes actual receipt/handoff. Download remote JSON bytes from the precise GitHub ref and record commit SHA, path, byte SHA and readback time. Confirm correct project, recipient and pinned lease/contract.
4. Write malformed `NOTE`-as-`HELLO`, wrong-recipient receipt, stale lease, duplicate message ID, altered object bytes and partial pagination cases using separate disposable fixture identifiers. Verify trusted poller rejects each and no unauthorized session/task transition occurs.
5. End Chat B; publish STOP and confirm there is **no automatic wake, STOP execution, or continuous agent polling**. Record local state `quiet` or `unknown` and whether an acknowledgement was actually observed.
6. Human manually starts a replacement ChatGPT conversation with a checkpoint/resume prompt. Verify it can recover task/Canon/lease/evidence from authentic readback, without changing project authority.
7. Run one actual configured game build/test command through approved .NET host or existing CI; record exact artifact and host/CI logs by digest. Interrupt a separate disposable run at an allowed boundary to verify recovery and UNKNOWN/readback behavior.
8. Independently review the exact candidate source tree SHA, submitted source and artifact bytes, receipts, validator output and QA identity separation. Have WG-M attempt stale-base/conflict promotion in the disposable environment and observe denial. Only then test an authorized promotion.
9. Record negative model-API billing/SDK scans and actual host/CI/GitHub provider usage. Never claim a dollar amount absent billing evidence.

**Evidence minimum:** full command/HTTP/GitHub-ref details (without tokens), file hashes, independent reviewer, source SHA, verified readback and machine-readable actual `PASS`/`FAIL`/`NOT_RUN`. Store witnesses/screenshots as hashed local artifacts with precise source identity. Mere test case configuration, a browser claim of success or an offline reference test cannot close a Tier C case. `qa.runner` defaults Tier C to `NOT_RUN` until this is independently witnessed; it does not automatically certify the pilot from an uploaded testimonial.
