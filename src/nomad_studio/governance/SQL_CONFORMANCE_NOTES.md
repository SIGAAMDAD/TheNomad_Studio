# CAB-D R9 — SQL conformance notes (frozen `initial_schema_v1.sql`)

This service assumes **only** the frozen R8/R9 initial 56-table SQLite schema; it does not install or modify schema. P2 must supply a writer capability limited to `v1_bible_editions`, `v1_bible_clauses`, `v1_bible_exceptions`, and `v1_owner_decisions`, and a bounded read-only snapshot callback. CAB-D must never be injected with a generic cross-domain write capability.

| Table | CAB-D writes | Frozen constraints | Runtime check |
|---|---|---|---|
| `v1_bible_editions` | Insert immutable proposal; compare-and-set activation/retirement | `project_id` FK; `(project_id,edition_id)` UNIQUE; `kind` DESIGN/TECHNICAL; `active` 0/1; active needs `owner_activation_ref`; one active `(project_id,kind)` partial UNIQUE | Trusted full-byte manifest readback, no duplicate edition, epoch strictly higher; owner proof and active-epoch CAS in transaction |
| `v1_bible_clauses` | Insert alongside proposed edition | `(edition_id,clause_id)` PK, kind REQUIREMENT/GUIDELINE/OPEN_AREA, `priority >= 0`, edition FK | Unique scoped clause ID, content digest and pinned file/excerpt bytes; no rewrite on activation |
| `v1_owner_decisions` | Insert proven, consumed activation / protected effect once | project FK, `(project_id,decision_id)` UNIQUE, proof_ref UNIQUE, expiration | IdentityPort verified action/subject/project proof; trusted attestation owner/epoch/expiry; same-transaction replay rejection |
| `v1_bible_exceptions` | None yet (no method in frozen BiblePort for exceptions) | composite project/edition/clause and owner decision FK | No request-provided exception may weaken REQUIREMENT. An explicit P2-owned owner-command route is necessary before enabling exception insertion. |

Read-only cross-owner tables: `v1_projects` (CAB-B), `v1_feature_contracts` (CAB-B), `v1_feature_runs` (CAB-J), `v1_source_leases` (CAB-I). These are never mutated by CAB-D. Effect decisions read active bibles, pinned feature contract and scoped active lease in a bounded read; CAB-I must revalidate branch-parent/lease immediately before committing a provider effect.

**Schema limits:** SQLite does not enforce manifest byte closure, monotonic edition epochs, same-project feature run and Bible-pair checks, owner proof freshness, or ancestor source leases. CAB-D enforces the first four, CAB-I owns atomic source-lease overlap and publication fences, and P2 owns service capability/transaction correctness. Activation replaces one kind atomically; a usable snapshot requires both active kinds. Protected actions are exact-owner-proof gated, never blanket major-impact gated.

**Integration:** `BibleRegistry(state, source_reader, owner_gateway)` and `AuthorityService(state, compliance_verifier, owner_gateway, clock_us)` implement the frozen method signatures. The owner gateway is `OwnerProofGateway(identity_port, attestation_reader, clock_us)`. `source_reader(repo, source_commit, request_readback)` must return trusted version-pinned `manifest_bytes`, complete `files` byte mapping, optional `clause_bytes` excerpts, and authentic `readback_ref`. No simulated or client-provided `verified` claims. `compliance_verifier(intent, checked_content, applicable_clauses)` must independently produce a schema-valid `BibleComplianceReceipt` from observed subject bytes. P2 validates the returned record against the frozen `$defs` and injects the strict table-owner writer capability.
