# WG-AG: Stable Worker Personas and Resume Context (S97–S99)

Source: Studio V1 R10, **local P1 source only**. This component is a project-neutral, non-privileged component implementing the existing frozen `Component` interface. Its logical identity is a registered `worker_id` with a pinned `role_id`; an ephemeral ChatGPT session is an execution surface and is never created here.

## Scope and module ownership

- Implementation: `nomad_studio.single_operator.personas.api.build_component(deps) -> Component`, `name='persona'`.
- Database: the pinned Studio V1 initial schema, state namespace **`persona`**, tables `persona_profiles`, `persona_active`, `persona_capsules`. Only the injected shared `StateStore` performs SQLite reads/writes. `persona_profiles` preserves history; `persona_active` enforces one active revision per worker. Contexts are append-only and chained by digest per `(worker_id, shift_id)`. No cross-domain SQL writes.
- The P2 composition root must wire the `persona` component and trusted ports. The `persona_*` tables are already created by the V1 initial schema; no migration registry or prior Studio version is involved. The source remains project-neutral.
- Profile and context shapes follow `persona_profile.v1.schema.json` (`NOMAD/SINGLE-OPERATOR/PERSONA/1`) and `worker_context_capsule.v1.schema.json` (`NOMAD/SINGLE-OPERATOR/CONTEXT/1`). Unlike these reference schema files, no provider automatically acquires trusted status through structure alone.

## Dependency injection: trusted-port proof shapes

`build_component({'store': StateStore, 'worker_registry': registry, 'job_context': context, 'host_observation': host, 'clock_us': clock})` is pure composition; it does not start a session, grant a credential, or call a provider during construction. `store` is the existing authoritative SQLite writer. `store.actor_epoch(principal_id)` must be supported to reject stale `VerifiedIdentity` instances. `clock_us() -> int` is an injected *trusted* microsecond clock; default is system wall clock. All non-storage providers are optional and **fail closed** when absent.

`worker_registry(worker_id) -> Mapping` must return `provider_verified: true`, an exact matching `worker_id`, `status: ACTIVE`, registered `role_id`, department from the twelve allowed values, nonnegative integer `assignment_epoch` and `policy_revision`. Caller-supplied role labels, assignments, and chat text are never substituted for this port. A persona is pinned to role/department/policy revision. It remains usable when *job assignment epoch* advances, provided role, policy, and active worker registration remain valid.

`host_observation(worker_id, shift_id, response_id, VerifiedIdentity) -> Mapping` must derive its result from the trusted host+gateway, not chat claims. Required exact matches: `worker_id`, `shift_id`, `response_id`, `principal_id`, `authority_epoch`, plus `ticket_ref` (bounded opaque identifier), `assignment_epoch`, `lease_generation`, and the booleans `provider_verified: true`, `ticket_redeemed: true`, `ticket_one_use: true`, `fenced: false`. The port is expected to ensure the ticket is a real fresh one-use redemption and is still attached to the same live host. The component compares these facts against the current context and stored session binding. It has **no ability to independently observe, redeem, or reopen ChatGPT sessions**.

`job_context(worker_id, shift_id, response_id) -> Mapping` must supply `provider_verified: true` and exact worker/shift/response IDs; current `role_id`, `department`, `assignment_id`, `assignment_epoch`, `lease_generation`, `job_id`, `scope_digest_sha256`, `policy_revision`, `authorization_ref`, `source_repo`, `source_commit_sha` (40 lowercase hex), `checkpoint_sha256`, `pending_message_ids` (up to 256 distinct bounded IDs), `unknowns` (up to 60 bounded single-line strings), `source_epoch`, `skill_id`, `skill_revision`, `skill_digest_sha256`, and `issuer`. All field limits and digest formats are validated. Skill revision/digest bind to *job context*, never to the persona. Different jobs in the same shift require a new capsule with an explicit prior-capsule digest.

The supplied test ports are **SIMULATED deterministic local fixtures**. They test denial/logic but are not actual registry attestation, host observation or production source/owner approval. At deployment, gateway/host ports must implement fresh trusted observation, ticket one-use enforcement, source/lease fencing and owner credential checks.

## CLOSED Component wire operations

Strict envelope versions: `NOMAD/CMD/1` for execute, `NOMAD/QUERY/1` for query; `domain='persona'`. `CommandEnvelope` requires bounded `request_id`, `idempotency_key`, `worker_id`; it is accepted only for three execute operations. `QueryEnvelope` requires bounded `request_id` and is accepted only for three query operations. Unknown keys and all other operation names are rejected. No generic freeform configuration, open prompt text, credentials, optional privilege flags, test PASS state or game code are accepted in payloads.

| Operation | Mode / exact payload object | Trusted actor prerequisites | Success result |
|---|---|---|---|
| `persona.register` | execute: `{ "settings": {"style_seed"?, "axes"?, "disagreement_style"?, "preferred_review_mode"?, "briefing_verbosity"?} }` | owner mTLS `persona:write`; live actor epoch; active registered worker | profile revision 1 and deterministic `change_receipt` |
| `persona.update` | execute: `{ "expected_revision": 1, "expected_digest": "<sha256>", "settings": {...} }` | same owner; active profile revision+digest CAS | next immutable profile revision, prior digest and change receipt |
| `persona.resolve` | query: `{ "worker_id": "...", "expected_revision"?: n, "expected_digest"?: "<sha256>" }` | `persona:read`; actor epoch; trusted registered worker | active profile and pinned digest |
| `persona.make_resume_capsule` | execute: `{ "shift_id": "...", "response_id": "...", "previous_capsule_digest"?: "<sha256>" }` | `persona:context`; live actor epoch; trusted worker, active profile, genuine observed host one-use ticket and current job-context port | bounded schema-valid capsule, `capsule_id`, digest, sequence, skill binding, prior digest |
| `persona.validate_context` | query: `{ "worker_id": "...", "capsule_id": "capsule:<sha256>" }` | `persona:context`; actor epoch; fresh host and job context readbacks | capsule digest and sequence if not stale |
| `persona.compose_launch` | query: `{ "worker_id": "...", "capsule_id": "capsule:<sha256>" }` | identical fresh validation | short deterministic style section, factual resume section, stage ordering metadata |

Every mutation also includes expected trusted `CommandEnvelope` fields, as applicable: `worker_id`, `shift_id`, `job_id`, `assignment_epoch`, `source_sha`. For capsule creation, `shift_id` must match payload; `job_id`, `assignment_epoch`, `source_sha` must match current trusted job context. `make_resume_capsule` ignores any purported identity/role/authorization in chat prose. Neither `resolve` nor launch composition calls external write ports.

All six operation names are **proposals for P2 gateway admission**, not automatically granted capabilities. Scope strings `persona:write`, `persona:read`, `persona:context` are authorization inputs from a previously trusted gateway; this module does not mint them. Valid query results are advisory and never confer game-source write, QA verdict, private HR or owner decision rights. Local successful context reports `evidence_class: TRUSTED_INJECTED_PORTS_LOCAL_ONLY`; this must not be confused with real-host verification.

## Invariants, compaction, idempotency, failures

The style axes are individually `0..4` and additionally constrained to ±1 from a department baseline. SHA256 over `(worker_id, role_id, department, style_seed, axis_name)` produces reproducible bounded variance. A request cannot supply its own arbitrary `style_fragment`, human biography, role, permissions or skill. The registered record contains fixed `EVIDENCE_BEFORE_PASS`, `NO_UNTRUSTED_APPROVAL`, `NO_PERSONHOOD_CLAIM`, `NO_PRIVILEGE_ESCALATION`, `NO_FABRICATED_MEMORY`. QA defaults to negative tests; engineering defaults to invariant review; creative contributors can disagree via evidence and owner escalation, not override approval. No simulated `PASS`, independent QA, human review or source authorization is promoted.

A context capsule carries only role/worker, assignment and lease epochs, persona revision/digest, current job and source, checkpoint digest, policy and authorization reference, selected inbox IDs, known unknowns, issuer and 5-minute expiry (also capped by `VerifiedIdentity` expiry). Source epoch, skill revision/digest, host-ticket reference and authority epoch are pinned in its separate stored `binding_json` and compared on every validation. For a single manual shift with multiple jobs, each later capsule must cite the exact prior digest; the predecessor becomes superseded. The shift chain is bounded to 256 contexts; no unlimited free-text chat histories are stored. Response IDs cannot be re-used with a different idempotency key. Fenced sessions and revised personas cannot rejoin old context.

`persona.compose_launch` returns stage ordering `immutable_policy > trusted_owner_grants > verified_job_source > pinned_skill_manual > persona_style > bounded_context > task_and_evidence`. It composes only the **priority-5 style and priority-6 factual resume**; the integrator/gateway must place them after higher-priority trusted sections. Actual *High* reasoning effort is configured by the human in the ChatGPT UI. Prompt text does not set this setting and never performs unattended wakeups.

Write idempotency is `(persona, operation, principal, idempotency_key)` with server-side SHA256 fingerprint of the command, protected by the shared `StateStore.transact_domain('persona', ..., fingerprint=...)`. Same key + same command replays the prior immutable receipt; reused key with another command yields `CONFLICT/IDEMPOTENCY_CONFLICT`. Active profile updates are CAS; attempts to change role/policy, replay old profile digest, change source/job epoch or substitute a prior context receive denial. Profile/history records are durable on the authoritative SQLite store only.

Representative fail-closed states/codes: `DENIED/INVALID_SCHEMA`, `DENIED/INVALID_SCOPE`, `DENIED/STALE_AUTHORITY_EPOCH`, `DENIED/PROFILE_STALE`, `DENIED/CONTEXT_STALE`, `DENIED/SESSION_NOT_VERIFIED`, `DENIED/CONTEXT_SUPERSEDED`, `CONFLICT/REVISION_CONFLICT`, `CONFLICT/CHECKPOINT_CONFLICT`, `CONFLICT/RESPONSE_REPLAY_CONFLICT`, `CONFLICT/IDEMPOTENCY_CONFLICT`, `NOT_RUN/REGISTRY_UNSUPPORTED`, `NOT_RUN/HOST_UNSUPPORTED`, `NOT_RUN/CONTEXT_UNSUPPORTED`, `UNKNOWN/STATE_UNAVAILABLE`, `UNKNOWN/HOST_UNKNOWN`, `UNKNOWN/CONTEXT_UNKNOWN`. All providers absent means no simulated registration/launch. No game-specific domain import, operation, schema or external write is present.

## Integration and independent verification

P2 needs to (1) verify the pinned V1 initial schema, install-wheel packaging, and recovery; (2) bind `build_component` to shared `StateStore` and verified `worker_registry`, `job_context`, `host_observation` ports; (3) separately extend/version gateway routing and permit scopes; (4) integrate coherent stale-lease/source-epoch checks and audit edge cases across sibling AH/AJ/AI without importing their private implementations; (5) add end-to-end host and capability tests and profile-revision invalidation; (6) decide profile revocation and retention/compaction policy. These are integration requests, not changes made by WG-AG.

P3 must independently re-run the isolated tests, schema conformance checks and mixed-worker trust/regression tests. P4 requires a **real**, observed same-ChatGPT-chat re-entry and a real one-use-ticket host receipt, independent of fixtures. P1 live-host, owner ratification, provider endpoints, skill installation and original 19-domain full integrated regression are **NOT_RUN**. The source-only tests establish local logic and no claimed production authority.
