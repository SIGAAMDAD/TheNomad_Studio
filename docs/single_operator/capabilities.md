## Integration surface

`nomad_studio.single_operator.capabilities.api.build_component(deps: Mapping[str, object]) -> Component` implements exactly three `CommandEnvelope` operations and three `QueryEnvelope` operations. Envelope versions are `NOMAD/CMD/1` and `NOMAD/QUERY/1`, domain `capabilities`, **full** operation strings below. All commands require a nonempty request ID and idempotency key. Query limits must be 1–500; query cursors are prohibited. Other domains, methods, versions and additional payload keys are denied. The original gateway does not recognize these operations; only the P2 integrator may admit them.

Mandatory injections: `store` (the **existing** shared `StateStore`), `authority_epoch(principal_id)->int`, and optionally `clock_us()->int` (microseconds UTC). The caller's `VerifiedIdentity` must be an independently established gateway identity, unexpired and at the exact live authority epoch. Scopes: `capabilities:admin` for registration, `capabilities:observe` for probes/observations, `capabilities:read` for all three queries. P2 must grant these exact new scopes through its authorized gateway policy, with no default wildcard and no implicit permission from a role/persona/skill prompt.

The six **closed** payloads (unlisted keys rejected) are:

| Operation | Method | Required keys | Optional keys | Output / denial |
| --- | --- | --- | --- | --- |
| `capabilities.register_host` | `execute` | `host_id`, `worker_id`, `origin`, `expected_revision`, `source_sha`, `capabilities` | none | `HOST_REGISTERED`, `STALE_HOST_REVISION`, schema/authority denial |
| `capabilities.probe` | `execute` | `host_id`, `capability_id`, `source_sha` | none | `PROBE_RECORDED`, `NOT_RUN`, `PROBE_UNVERIFIED`, `STALE_SOURCE`, `PROBE_PERMISSION_SHORTFALL` |
| `capabilities.observe` | `execute` | `host_id`, `shift_id`, `event_kind`, `session_epoch` | none | `HOST_OBSERVED`, `NOT_RUN`, `HOST_UNVERIFIED`, `FENCED_SESSION`, `INVALID_TRANSITION` |
| `capabilities.validate_job` | `query` | `host_id`, `source_sha`, `required`, `require_unattended` | `shift_id` | `CAPABILITIES_VERIFIED` or `CAPABILITY_SHORTFALL` with reasons |
| `capabilities.list_shortfalls` | `query` | same as `validate_job` | `shift_id` | `SHORTFALLS_LISTED` with `eligible` flag; never grants admission |
| `capabilities.measure_capacity` | `query` | none (`{}`) | none | separate counts and `live_production_qualification=NOT_RUN` |

`origin` is one of `REGISTERED`, `MANUAL_CHAT`, `SYNTHETIC`. It is *registration configuration*, not a host attestation. `capabilities` is a list (0–100) of closed `{capability_id, kind, version, permission_scopes}` items, unique IDs, with `kind` from `tool_execution`, `workspace_access`, `compiler`, `external_connector`, `build`, `upload`, `readback`, `skill_loading`, `host_wake`, `reasoning_setting`. Tool IDs, versions, scopes and their mappings are all **configuration**; no hardcoded engine, audio middleware, repository or IDE commands. A request's `required` list (1–100) contains closed `{capability_id, version, permission_scopes}` entries. Versions and permission capabilities must match **exactly**. An exact source SHA-256 is required; a changed host revision, authority epoch, resource scope, version or expiration invalidates the old proof.

`capabilities.measure_capacity` reports distinct `registered_worker_ids`, `manual_chat_registration_claims`, **independently observed** `manually_opened_chats`, `verified_reachable_shifts`, `actively_processing_shifts`, `verified_reentry_shifts`, `simulated_actor_ids`. Counting 600 or 800 synthetic registrations creates no ChatGPT session and no live fleet proof. Expired/fenced sessions do not count as reachable/active. A mere `High` setting claim cannot satisfy `reasoning_setting`.

## Exact injected trust port shapes

**Tool probe** (optional, read-only): `probe_port(context)->receipt` and `probe_verifier(receipt, context)->binding`. `context` keys: `host_id`, `capability_id`, `version`, `source_sha`, `required_permissions` (exact list), `host_revision`, `authority_epoch`. The returned `receipt` is a **closed** `NOMAD/SINGLE-OPERATOR/CAPABILITY/1` datum with host/capability ID, observer principal, version, `source_revision_sha256`, status, surface, resource permissions, timestamp range, input/output SHA-256 digests and nonempty evidence references. The verifier must independently validate source of evidence and signed/trusted observer, not merely validate its JSON. It returns a mapping with `verified: true`, **all context keys unchanged**, and `receipt_sha256` matching canonical JSON. A bare `True` is refused. `AI_CLAIM` and `SYNTHETIC_TEST` observers never qualify for real availability; only independently verified `TRUSTED_HOST` or `TRUSTED_GATEWAY` and `PROBED_AVAILABLE` admit work. An observed `PROBED_UNAVAILABLE` records an explicit negative result. Missing port / binary / live provider yields `UNKNOWN/NOT_RUN`; a model response cannot fill the gap.

**Live host observation** (optional, read-only): `host_observer(context)->observation` and `host_verifier(observation,context)->binding`. The context is closed: `host_id`, `shift_id`, `worker_id`, `event_kind`, `session_epoch`, `host_revision`. The observation must have exactly the candidate `NOMAD/HOST-OBSERVATION/1-CANDIDATE-R10` fields from R10, including `host_session_ref`, `manual_owner_launch_receipt_ref`, observer principal, event digest, non-null signature reference and UTC time. The independent verifier's returned binding must contain `verified: true`, all context fields unchanged, `observation_sha256` of canonical bytes, actual `session_ref`, and `manual_launch_verified: true`. Actual verification of receipt/signature/manual launch and host-session re-entry is the **external verifier's** responsibility. The schema and arbitrary strings do not provide it. A simulated `origin` cannot become real. A `MANUAL_CHAT` registration plus independently verified `SESSION_BOUND` is the minimum to mark a chat reachable, and is **not** a wake test.

Event names: `SESSION_BOUND`, `ADDRESSED_MESSAGE`, `YIELDED`, `SECOND_JOB_AFTER_IDLE`, `HEARTBEAT`, `REVOKED`, `FENCED`, `UNSUPPORTED`. A real second job must be observed *after* an observed first-job `WORKING -> YIELDED` transition, on the **same** host session, manual launch reference and session epoch, before an unattended admission can pass. Events with stale timestamps, wrong epoch, wrong session/launch or reused observation IDs are fenced/rejected. `HEARTBEAT` is an independently observed lease renewal only. The default maximum heartbeat lease is 60 seconds, configurable 1–300 seconds. `SECOND_JOB_AFTER_IDLE` does not launch a chat; it records the outcome only if the host actually observed a re-entry. Missing real host verifier returns `UNKNOWN/NOT_RUN`.

## Optional P2-hosted runtime adapter (not a seventh public operation)

`HostShiftAdapter(component, send_port=..., delivery_port=..., verify_delivery=..., authorize_message=..., authorize_budget=..., max_attempts=3)` is local, **not** automatically gateway-admitted. Methods: `budget(shift_id,units,authorization_ref,identity)`, `dispatch(shift_id,immutable_message,identity,reentry_probe=False)` and `disconnect_expired(shift_id,identity)`. They require `capabilities:dispatch`, live identity epoch and fresh, unfenced, correctly registered session. A refilled budget requires independently verified authorization mapped to exact `shift_id`, `units`, `authorization_ref`, `principal_id` and `verified: true`. Message authorization is exact SHA-256, authorization receipt ref, recipient and epoch plus `verified: true` from a separate injected authorizer; a bare `True` fails. `send_port` receives an immutable addressed `NOMAD/LIVE-WORKER-MESSAGE/1-CANDIDATE-R10` message and context. Its return value is **not** evidence that delivery succeeded. `delivery_port(context)` plus a separate `verify_delivery(proof,context)` binding all context keys, canonical proof SHA-256 and `verified: true` may record a `NOMAD/LIVE-DELIVERY/1-CANDIDATE-R10` attempt/ACK. Messages remain immutable; attempts/ACKs live in a separate append-only table. One message has at most `max_attempts` (default 3, hard cap 5). The first attended job can be sent with observed reachability; while IDLE_WAIT without reentry proof, **only** a bounded CONTROL `reentry_probe` may be sent. This probe never grants an unattended job. A new independently observed `SECOND_JOB_AFTER_IDLE` is still required to admit subsequent unattended jobs. Budget zero fences dispatch; lease expiry can be fenced by `disconnect_expired` and cannot be undone by user text. If any trust/send/readback port is absent: `NOT_RUN` or an explicit denial, **no inferred delivery or ACK**.

P2 must assign execution ownership, revalidation and authorization/readback semantics before using this adapter in a real service. Runtime send is an optional *injected port*; no P1 test or setup executes an external write. P1 test ports are synthetic and can validate state-machine behavior but do not produce real host proof.

## Persistence, events and replay

The `capabilities` tables (`cap_hosts`, `cap_receipts`, `cap_shifts`, `cap_host_events`, `cap_messages`, `cap_deliveries`, `cap_idempotency`) are created by the single pinned Studio V1 initial schema. There is no per-module migration API, resource twin, or development database upgrade. State changes occur only via `StateStore.transact` and reads only via `StateStore.read`; there is no second SQLite connection or root schema change. Mutations append `capabilities` `DomainEvent`s: `HOST_REGISTERED`, `CAPABILITY_PROBED`, `HOST_OBSERVED`. Idempotency is keyed by `(principal_id, idempotency_key)` and hashes canonical operation + payload + principal + epoch; identical replay returns original result, divergent replay returns `IDEMPOTENCY_CONFLICT`. Host observation IDs are separately unique and must have matching canonical evidence; session epochs fence replays. `MESSAGE_IMMUTABILITY_CONFLICT`, `MESSAGE_RECIPIENT_CONFLICT`, `REPLAY_LIMIT`, `FENCED_SESSION`, `BUDGET_STOP`, `STALE_AUTHORITY`, `STALE`, `UNVERIFIED_REENTRY`, `PERMISSION_SHORTFALL`, `NOT_CONFIGURED` are explicit fail-closed outcomes/reasons. Unexpected store or provider failure returns `UNKNOWN` and is **not** treated as acceptance.
