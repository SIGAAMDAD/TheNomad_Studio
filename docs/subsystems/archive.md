# WG-L — Auditor compressed database archives and independent restore

Contract: `NOMAD/ARCHIVE/1`, `NOMAD/CMD/1`, `NOMAD/QUERY/1`, frozen `Component`, `StateStore` and `DomainEvent` from `nomad_studio.contracts.v1`. Entry point `nomad_studio.archive.api.build_component(deps)`. No other module import, no shared ABI edits, no schema ownership outside `archive_*` tables.

## Intended trust boundary

An authenticated **Auditor** holds `archive:auditor`, a distinct **restore witness** holds `archive:witness`, and archive readers hold `archive:read`. All must be `VerifiedIdentity` established by the upstream gateway, unexpired, and accepted by the injected live `authority.valid(identity)` epoch/revocation port. The arbitrary `worker_id`, `actor_claim`, job ID, and receipt payload are not authentication. `approvals.approved(...)` independently confirms an owner-approved archive job and its exact evidence scope; a mere Auditor scope cannot start arbitrary archive jobs. The witness must come from an independently trusted issuer and `witness_verifier.verify(...)` must establish that a separate actor actually decompressed, restored and inspected the archive, then bound the attestation to the exact archive digest and subject. The module cannot self-issue either approval or witness credentials.

The archive index stores only archive/provenance state, never live jobs, leases, permissions or authority; no archive command deletes source, Drive, GitHub, receipts, original event history or changes production writers. Retention and deletion decisions require an independent owner-authorized system (not implemented or exposed here). Historical source and receipts are stored as opaque bytes; they are never imported or executed as old controllers.

## Deployment ports and composition

| `deps` name | Contract / role | Required |
| --- | --- | --- |
| `archive_root` | Explicit local/private `Path` on stable filesystem; output `.sqlite.gz`, or `.sqlite.gz.enc` | Always |
| `state` | WG-A `StateStore`; uses `archive_*` tables installed by the pinned Studio V1 initial schema | Always |
| `authority` | Trusted gateway live policy/epoch object: `.valid(VerifiedIdentity) -> bool`; fail closed | For all calls |
| `approvals` | Trusted owner-approval adapter: `.approved(job_id, approval_ref, principal_id, evidence_refs) -> bool` | `open_job` |
| `snapshot` | WG-A adapter: `.capture(destination: Path, *, job_id: str) -> {sha256: 64-char lowercase hex, integrity_ok: true, source_generation: str}`. Writes a **consistent offline SQLite backup** to a private path, not a live connection provided to WG-L | `snapshot` |
| `evidence` | WG-J/K/F adapter: `.fetch(kind, reference, revision) -> bytes`; MUST independently read exact pinned provider bytes and hash against approved reference, no model-supplied bytes | `compress` when refs nonempty |
| `witness_verifier` | Independent issuer adapter: `.verify(receipt, *, identity, stored_sha256, archive_path) -> bool`. Its truth MUST derive from cryptographically authenticated independent restore/readback evidence, **not** command payload | `restore_proof` |
| `encrypted` | Boolean. Default `False`; plaintext gzip is a temporary local reference codec only, not the owner's final codec decision | Optional |
| `cryptor` | Independently owned key custodian: `.encrypt_file(plain_path, cipher_path, *, archive_id)`, `.decrypt_file(cipher_path, plain_path, *, archive_id)`. Must be authenticated encryption with rotation/key IDs and fail-closed tamper detection | If `encrypted=True` |

The injected adapter shapes are local integration seams, **not new shared wire ABIs**. The integrator must implement them against the frozen Component envelopes or approved WG-A snapshot primitives. WG-L neither opens the live StateStore SQLite file nor creates a second mutable Studio SQL owner. Only offline SQLite artifacts are opened with `sqlite3`.

**External blockers:** actual approved destination/off-host replication and readback, owner codec choice (zstd proposed; stdlib gzip implemented), retention policy, real key custody and authenticated encryption provider, independent restore witness infrastructure, actual gateway/connector authentication, remote Git/Drive evidence fetch, and final external provider verification are **NOT_RUN**. A local fake witness/cryptor is functional-test evidence only. Local `archive_root` is **not** off-host disaster recovery. Archive creation or local tests confer no permission to delete anything.

## Closed command schemas

Every command has `version='NOMAD/CMD/1'`, `domain='archive'`, `operation='archive.<verb>'`, nonempty `request_id`, `idempotency_key`, `job_id`. `archive_id` is `[A-Za-z0-9][A-Za-z0-9_-]{0,79}` and the resulting basename is fixed by code, not request-supplied filesystem paths. Unknown fields or major versions are rejected.

| Command | Payload | Required authority | Transition and event |
| --- | --- | --- | --- |
| `archive.open_job` | `{archive_id, approval_ref, evidence_refs:[{kind,reference,revision,sha256}]}`; kind one of `source`, `receipt`, `historical`, `artifact`, `document`; immutable SHA-256, all entries unique | Auditor scope **and** trusted approval port | absent → `OPEN`; `ArchiveJobApproved` |
| `archive.snapshot` | `{archive_id}` | Same Auditor principal, same approved job, trusted snapshot adapter | `OPEN` → `SNAPSHOTTED`; integrity-check offline SQLite and readback SHA; `ArchiveSnapshotVerified` |
| `archive.compress` | `{archive_id}` | Same Auditor, trusted evidence adapter | `SNAPSHOTTED` → `COMPRESSED` only after source and evidence hashes, per-shard readback, manifest verification; `ArchiveCompressionVerified` |
| `archive.seal` | `{archive_id}` | Same Auditor | `COMPRESSED` → `SEALED_UNWITNESSED` after compression integrity checks, optional encryption roundtrip, fsync, atomic link/no overwrite, and SQL receipt; `ArchiveSealedUnwitnessed` |
| `archive.restore_proof` | `{archive_id, witness_ref, archive_sha256, manifest_sha256, snapshot_sha256, record_count, proof}` | Distinct witness principal with `archive:witness`, independently authenticated proof | `SEALED_UNWITNESSED` → `WITNESSED` only after independent receipt verification; `ArchiveIndependentlyRestored` |

Returned `Outcome.state`: `ACCEPTED`, `DENIED`, `BLOCKED`, `CONFLICT`. `Outcome.code` is the transition status on acceptance or frozen error code (e.g. `INVALID_SCHEMA`, `INVALID_SCOPE`, `OWNER_APPROVAL_REQUIRED`, `EXPIRED_GRANT`, `REVOKED_GRANT`, `SOURCE_SHA_MISMATCH`, `SELF_REVIEW`, `IDENTITY_UNVERIFIED`, `IDEMPOTENCY_CONFLICT`, `NOT_CONFIGURED`). Unaccepted calls never advance archive status. `COMPRESSED` or `SEALED_UNWITNESSED` returns `status: NOT_VERIFIED`; **only `WITNESSED` may return `status: VERIFIED`**. Transport exceptions or disk faults can leave an unknown physical effect requiring durable-state reconciliation; they must not be reported as PASS.

`archive.catalogue` is query-only, `version='NOMAD/QUERY/1'`, `domain='archive'`, `operation='archive.catalogue'`, reader scope required, `limit=1..100`. Payloads: `{}` returns bounded ordered index; `{archive_id}` returns status and hashes; `{archive_id, reference, kind?, revision?}` verifies the sealed file against the stored digest and returns matching *provenance manifest entries* (SHA, source version, per-shard hashes), never raw hidden archive job/permission tables. `QueryEnvelope.cursor` is not implemented for paging; cursor must be omitted by integrator until pagination is agreed, or each query uses a capped first page.

Idempotency key is persisted in `archive_idempotency`, bound to the operation, job, payload, subject/source assignment and authenticated principal/authority epoch; `request_id` may change across an otherwise identical retry. Replays return the persisted receipt; the same key with changed command/actor is `CONFLICT`. Write transactions append an immutable `DomainEvent` via `StateTx.append_event` and store the receipt atomically. The StateStore owns transaction ordering and the single pinned V1 schema bootstrap. Events contain hashes and references, not source bytes, credentials or witness secrets.

## Archive format and integrity model

`NOMAD/ARCHIVE/1` uses an **offline SQLite archive database** with `header(key,value)`, `entries(entry_id,kind,reference,revision,byte_size,sha256,shard_count)` and `shards(entry_id,ordinal,sha256,payload)`. First entry is a verified consistent SQLite authority snapshot. Remaining entries are historical source/document/asset bytes and immutable receipts fetched through pinned provider adapters. Fixed chunk size: 1 MiB; every shard has SHA-256, every entry has full SHA-256 and byte size, every archive has canonical ASCII JSON logical manifest, and the manifest itself is SHA-256 checked. The payload is gzip-compressed (`mtime=0`; no filename header). The file's SHA-256 is pinned separately from the *logical* manifest digest. Identical archive IDs, snapshots, evidence and revisions yield equal logical manifest bytes independent of caller order. The database is immutable after building and read with `immutable=1`, integrity checked, and every byte of every record is reread/hash-verified on inspection.

`format.inspect_archive(path, restore_snapshot_to=None, max_bytes=...)` is an independent offline restore/check primitive. Decompresses to private scratch; validates SQLite integrity, schema, per-shard byte order/digests, manifest digest and contents, and snapshot count. With `restore_snapshot_to`, reconstructs the original SQLite snapshot, hashes it, integrity-checks it and creates the requested **offline** destination without overwrite. It never points a service at restored data, migrates a live database, switches writer roles or deletes originals. `format.restore_evidence(path, destination_dir, *, kind, reference, revision)` independently validates the entire archive and restores one exact original source/receipt/document blob as a content-hash-named `.bin` into an offline directory, refusing overwrite and never using provider references as local paths.

The compression and archive finalization are separate. Compression writes only `.pending/<archive_id>/archive.partial`; a corruption/throw/crash there never publishes a final `.sqlite.gz`. Sealing re-verifies `.partial` and atomically hard-links a verified final inode to a deterministic path, without overwriting existing archives, then records the `SEALED_UNWITNESSED` event. On crash after the hard link but before the SQL commit, a retry checks the final content and reconciles the missing SQL transition. Every stage output is same-root local; deploy on one archive-service owner process, with a local filesystem that supports hard links and directory fsync. If these guarantees are absent, backend must fail/`NOT_SUPPORTED` rather than silently claiming an atomic seal. `.pending` retains temporary recovered work and may contain plaintext, even if encryption is requested; protect the archive host and privately purge only those **staged copies** under an explicit host lifecycle policy after durable seal. It never purges immutable input history.

## SQL schema / resource bounds / failures

The `archive_*` catalogue and idempotency tables are defined in the pinned V1 initial schema `state/schema_v1.sql`. `archive_jobs` records job identity, approved ref, creator principal, sorted approved evidence descriptors, state, snapshot/manifest/container digests, entry count, encryption flag and independent witness provenance; `archive_idempotency` stores exact command fingerprint and response. Index `archive_jobs_state`. This is a catalogue and audit index, **not** a new authority database or replacement for WG-A's event journal.

Limits: `archive_id <= 80`, at most 10,000 entries including snapshot, `<=128 MiB` per fetched evidence record, `<=1 MiB` per stored shard, maximum 32 GiB offline expanded archive (configurable downwards via the pure inspection helper), `limit<=100` catalogue rows. Gzip decompression is bounded before SQLite inspection. The per-entry memory footprint for the snapshot is streamed shard by shard; evidence adapters currently return a `bytes` object per record, so memory for an individual provider object remains capped at 128 MiB. No stream transfer of external evidence at this contract version. `SHA256` gives corruption detection, while trust in provenance comes from independently pinned source fetch/owner approval and independent restore witness.

Unknown keys, unsupported schema/versions, bad identities/scopes, stale authority epochs, unapproved evidence, fraudulent digest, malformed SQLite input, corrupt/truncated gzip and tampered SQLite shards are denied. Mid-compression and mid-seal interruptions leave recoverable private stages; the local service does not infer success from a partial file. Filesystem I/O, provider fetch, encryption and independent readback are outside WG-A SQL write transactions. SQLite writer cutover, off-host restore, production deletion and new permissions are absent by design.

## Integration instructions

1. Initialize the shared `StateStore` from the pinned Studio V1 initial schema before `build_component`. The archive module does not register SQL migrations or open a second live SQLite connection.
2. Compose the trusted gateway/epoch, approval, WG-A backup and independent pinned-history evidence adapters. Only adapters may access other subsystem Component facades; WG-L itself imports none.
3. Configure a private archive root and choose local filesystem capacity/atomicity. Owner must decide codec, off-host destination, retention rules and encryption-key custodian before production acceptance.
4. Register a separately credentialed restore witness that invokes `inspect_archive(..., restore_snapshot_to=OFFLINE_PATH)`, verifies the restored snapshot digest/SQL records and every archived evidence entry, checks the off-host archive readback, then emits a signed/verified receipt. Inject a verifier that validates those receipts through an independent issuer.
5. Exercise one full real backup → off-host publish → remote fetch → independent restore → witness registration chain. Mark it **NOT_RUN** until observed. Never use a model-declared PASS, fake cipher, or local self-restore as equivalent proof.
6. Pass `archive.catalogue` results to WG-M's health reporting as read-only metadata. No migration/cutover/delete integration seam exists in WG-L.
