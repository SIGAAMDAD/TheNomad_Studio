# ChatGPT integration — V1.6 manual High setup

The only supported AI execution path is **a human manually opening a GPT-6 High chat**. Do not create/activate scheduled worker tasks, event-triggered ChatGPT Work tasks, PR-to-AI hooks, API model dispatch or recurring paid task subscriptions. Historical S00–S09 and W01–W06 identities and receipts remain archived, not executable.

1. Establish the owner-approved bounded job, source repo/branch and exact baseline, owned paths, acceptance criteria and reviewer. Read `studio/v16/worker/README.md`, `studio/v16/worker/PROFILES.v1.json`, and the specific role entry in `ROLE_REGISTRY.v1.json`. Use `MANUAL_LAUNCHERS.md` or the local `manual_kernel.py launch` CLI to populate a concise prompt for that role.
2. Attach the supplied ZIP snapshot and compact resume capsule when available. Begin local work immediately. No connector access is necessary for offline work, and no preflight consent request is needed until an actual GitHub/Drive connector operation is required.
3. Before the **first** GitHub/Drive connector request in the chat, name the exact provider, resource/ref/path, operation and reason; ask for owner confirmation. A signed-in shared account is not a worker/head privilege proof. Without an isolated gateway, all implementation remains local patch-only.
4. At each response boundary, worker returns its local source patch, exact hashes, changed paths, commands/exit codes, open acceptance, evidence-based report card and one RUN-V16 resume capsule. Independent QA verifies the exact candidate; independently authenticated owner/head integrates and publishes only with real readback. Never treat a worker's own local Git SHA as a GitHub commit.
5. For supervision, deterministic controller/CI may inspect submitted receipts and send ordinary alerts. They **must not** launch an AI chat; the human opens any continuation as a new attempt. WG-G later removes obsolete router and CI entrypoints without modifying historical receipts.

See [`studio/v16/contracts/RUN-V16.md`](../studio/v16/contracts/RUN-V16.md) and [`studio/workforce/source_targets.v1.json`](../studio/workforce/source_targets.v1.json). The current workgroup implementation does not establish owner-gated launch, isolated credentials or deployed database authority.
